# Steering: AI Data Policy

What data may reach a model provider, in what form, and how long AI artefacts are kept. It puts
[Constitution Article XII.4](../constitution.md#article-xii--ai-agents-and-data) into practice. The retriever code step
(`server/ai/steps/retriever.ts`) and the MCP server ([025-mcp-tooling](../specs/025-mcp-tooling/)) apply it
in code; the eval suite checks it (EVAL-CODE-005).

**Version:** 1.0.0 · **Date:** 2026-11-17 · **Change request:** [CR-20261117-1](../changes/CR-20261117-1-ai-agents.md)

## 1. Basis
- The workbook holds **fictional demo data only** ([ADR-0006](../adr/0006-fictional-demo-dataset.md)). There are no
  real customers, people, products or notes anywhere in the project.
- AI features are off unless `AI_ENABLED=true` (Article XII.8). With AI off, no data leaves the machine.
- The only model provider is the Anthropic API, called from the server (`server/ai/`, planned), never from the browser.
  The key is read from the environment (`ANTHROPIC_API_KEY`) and is never committed, logged or sent to the browser.

## 2. Field allow-list (what the Retriever may put in a fact sheet)
| Sheet | Fields sent | Form |
|---|---|---|
| `customer` | `id`, `parent_name` | As stored |
| `use_case` | `id`, solution name, use case type name, status name, subsidiary name, department name, `expected_launch_date`, `value_snippet`, `note` | Names resolved from lookups; free text wrapped as data (§4) and cut to 1 500 characters |
| `event` | `id`, event type name, subsidiary name, `event_date`, `stage`, `attendee_count`, `meeting_notes` | Free text wrapped as data and cut to 1 500 characters |
| `customer.executive_summary` | Not sent | The draft is written from activity, not from the old summary |
| `personnel`, `stakeholder` | **Names only**, and only when linked to a sent record | Emails and personnel IDs are never sent |
| Everything else (legacy `use_case` columns, history, link sheets, `deleted` rows) | Not sent | — |

Soft-deleted rows (`deleted = true`) are never sent, matching every other read in the app (Article II.4).

## 3. Redaction
- **Emails:** any text matching an email pattern is replaced by `[email]` before it is sent, even inside notes.
- **Phone numbers and URLs with query strings:** replaced by `[phone]` and `[link]`.
- The fact sheet lists the redactions applied (`redactions` in [fact-sheet.v1](../contracts/fact-sheet.v1.schema.json)),
  so a reviewer can see what the model did not receive.

## 4. Data is data, not instructions
Free text from the workbook is placed inside delimited data fields and the system prompt states that instructions
found in data must not be followed (AIB-SAFE-001). Prompt-injection cases are part of the eval dataset (EVAL-DATA-003). The eval judge receives only a case's fact sheet
and the draft built from it, never model or configuration details (EVAL-JUDGE-009).

## 5. Real customer data (not allowed today)
Before any real customer data may be sent to a model, a change request must specify: authentication
(SEC-EXPO-002), a data processing agreement with the provider, the provider's retention setting, and an update to this
policy's allow-list. Until then the allow-list applies only to the fictional workbook and to fixtures generated by
`scripts/generate_demo_workbook.py`.

## 6. Storage and retention of AI artefacts
| Artefact | Where | Contains | Kept |
|---|---|---|---|
| Run checkpoints | `../data/ai-runs/<run_id>.json` (outside the repo) | Step outputs (fact sheet, hand-offs, draft) | 30 days, then deleted on server start |
| Traces | `../data/ai-runs/traces/*.jsonl` | IDs, step, model, tokens, cost, latency, outcome; **no free text** | 90 days |
| Eval runs | `evals/runs/` (git-ignored) and `evals/reports/` (committed) | Outputs from fictional fixtures only | Reports kept; raw runs local |
| MCP audit log | `../data/mcp-audit.jsonl` | Tool, argument hash, duration, result size; **no free text** | 90 days |
| Server logs | Console | Run ID and outcome; no free text, no key | Not stored |

None of these files is committed except eval reports, which are built from fictional fixtures only.

## 7. Change control
Widening the allow-list, adding a provider or changing retention is a change request against this file and
Article XII; narrowing it is a PATCH-level edit with a note in the spec that enforces it.
