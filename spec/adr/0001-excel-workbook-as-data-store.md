# ADR-0001: Excel workbook as the data store

- **Status:** Accepted (recorded retroactively, 2026-11-11)
- **Context owner:** Code App Demo team

## Context
The app replaced a Power Apps application backed by SQL stored procedures (names such as `usp_getSolutionStatuses`
remain in comments). The SQL source was not available; the only data source was a Power BI export (`Terra_Data.xlsx`).
The team needed a working app quickly, with data that maintainers can inspect and fix by hand.

## Decision
Use a single Excel workbook (`code-app-data.xlsx`) as the database: one sheet per table, column names kept from the
old SQL tables, generated by `scripts/build_workbook.py`. The app reads and writes it through a small Node service
(see ADR-0002).

## Consequences
**Positive**
- No database to install; maintainers fix lookups directly in Excel.
- Table/column names match the old system, easing a later move back to SQL.

**Negative**
- Whole-file rewrite on every change (PERF-SPEED-005, PERF-SPEED-006); formatting in the workbook is not preserved (STO-SAVE-008).
- File locking with Excel open (handled as 423, REL-SAFE-002) and the "unsaved Excel changes win" hazard (REL-SAFE-006).
- No multi-user concurrency, no transactions across files, no referential integrity enforcement.

## Revisit when
More than one concurrent user, more than ~50k rows, or a need for audit history. Migration path: keep the HTTP API
contract ([workbook-api spec](../specs/014-workbook-api/design.md)) and swap the storage engine behind it.
